# 3. Agent Tool Surface, Mutation Policy, and MCP Protocol Design

Date: 2026-08-15

## Context

The GYMBro Agent Engine orchestrates athletic intelligence across telemetry analysis, nutrition logging, bloodwork biomarkers, and dynamic multi-horizon calendar programming.

Previously, tool definitions were fragmented across multiple disparate modules (`app/coach/agent_tools.py`, `app/agent/tools.py`, `app/tools/registry.py`) with loose dictionary returns. Furthermore, questions remained regarding:
1. Whether to expose tools via standard Model Context Protocol (MCP) server endpoints vs native in-process function calling.
2. How to safely handle destructive or bulk mutations (e.g., committing 16-week training plans or deleting workouts).
3. How to guarantee multi-tenant security and athlete data isolation across LLM invocations.
4. How tools return both conversational context to the LLM and interactive widget envelopes (`gymbro.widget/v1`) to the Expo mobile client.

## Decision

1. **Hybrid Core-Adapter Pattern**:
   - **Domain Tool Core (`app/tools/`)**: Implemented as pure Python functions with strong Pydantic typing and standardized `ToolResult` models.
   - **Native In-App Adapter**: In-process schema generation and execution for the primary Flask/Expo Agent Engine (supporting Gemini, OpenAI, xAI Grok, and Local LLM), ensuring sub-50ms execution with zero serialization overhead.
   - **MCP Server Adapter (`app/mcp/`)**: Future-ready Model Context Protocol server (FastMCP / MCP Python SDK) exposing the identical tool catalog over `stdio` and authenticated `/api/mcp` routes for external agent environments (Antigravity, Cursor, Claude Desktop) without requiring changes to core tool implementations.

2. **Nuanced Safety & Mutation Policy**:
   - **Read / Query Tools (Autonomous)**: `get_recent_activities`, `get_wellness_metrics`, `get_biomarker_history`, `get_calendar_events`, `get_athlete_profile` execute immediately with no confirmation overhead.
   - **Bulk / Generative / High-Impact Mutations (Two-Phase Proposal)**: `propose_training_plan` generates a multi-horizon training block and returns a `calendar_proposal` widget card. The actual database commit is deferred until the athlete taps "Commit to Calendar" or explicitly confirms in chat.
   - **User-Directed Single Edits & Explicit Deletions (Autonomous on Direct Intent)**: If the athlete explicitly requests a specific edit or deletion (e.g., *"Delete tomorrow morning's workout, I have a meeting"*), the agent executes the change directly. The agent then proactively suggests intelligent rescheduling options (e.g., *"Removed your 8km morning run. Would you like to move it to Thursday afternoon?"*).
   - **Ambiguity & Draft Safety**: If an edit request is ambiguous or alters a pending, uncommitted proposal, the agent emits an updated proposal card rather than performing an unconfirmed commit.

3. **Static Server-Enforced Context Injection**:
   - `user_id` and athlete tenant scope are strictly extracted by server middleware from authenticated session tokens (JWT / API Key / MCP handshake).
   - Any `user_id` parameter generated by the LLM is stripped and overwritten by the runtime gateway, preventing cross-tenant leakage or hallucinated user data access.

4. **Standardized `ToolResult` Pydantic Contract**:
   All tools return a unified schema:
   ```python
   class ToolResult(BaseModel):
       success: bool = True
       observation: str                                 # Concise summary fed back to LLM context
       ui_payload: Optional[Dict[str, Any]] = None      # gymbro.widget/v1 envelope for Expo client
       data: Optional[Dict[str, Any]] = None            # Raw structured data for MCP/API consumers
       error: Optional[str] = None
   ```

5. **External Calendar & Conflict Awareness Seam**:
   - Integrated with Issue #24 (`Implement External Calendar Integration for Smart Schedule Conflict Detection`) to expose busy/free time analysis (`check_schedule_availability`, `get_free_training_slots`) so the agent never schedules workouts over personal or work commitments.

## Consequences

- Eliminates redundant tool definitions across `app/coach`, `app/agent`, and `app/tools`.
- Ensures zero latency penalty for mobile in-app coaching while maintaining full MCP compliance for future developer agent tools.
- Protects user calendar integrity with clear separation between autonomous reads, direct user edits, and two-phase plan proposals.
- Provides a consistent typing contract feeding both the LLM conversational stream and Expo native UI widgets.
